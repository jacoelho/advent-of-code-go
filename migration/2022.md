- Crate parsing resolves labeled drawing columns and validates transfers. Marker detection uses the datastream bytes without its line terminator and reports missing markers.
- Filesystem listings preserve file identity, make repeated listings idempotent, reset on `cd /` and retain empty directories. No required deletion returns zero.
- Rope tracking includes its initial position. The CRT applies register changes after their instruction cycles, renders exactly 240 pixels and derives `PLULKBZH` through shared OCR. The official nonalphabetic example is checked as a raster.
- Monkey IDs determine turn order; later monkeys can process newly received items in the same round. Exact integer operations precede relief or modular reduction. The supported input has at least two monkeys, positive divisors, valid references and no self-targets; self-targets return an explicit error.
- Reverse heightmap BFS serves both parts. Packets use strict list syntax and comparison, and inserted dividers retain their identity even beside equal-valued input packets.
- Sand uses an implicit infinite floor. Rock segments must be orthogonal; the fall path can reuse an unchanged prefix after a grain settles.

## Supported equation class

Day 21 validates the entire expression graph and evaluates exact integer arithmetic. Part two supports one human-dependent root side and exactly one dependent operand at each step along an invertible path. Constants and inverses use bounded `big.Int` values with exact division. The selected human value is substituted into both original root branches and accepted only when both are defined and equal.

Zero multiplication with zero target, and zero numerator with zero quotient, are explicitly unsupported noninvertible equations. They are not classified as globally ambiguous: exact divisions inside the dependent expression may restrict its domain to a unique human value. Regression fixtures preserve that distinction. A general solver for noninvertible or multiple-dependent expressions was rejected as unnecessary for the accepted program class.

## Generic cube folding and periodic routing

Day 22 preserves ragged map spaces and parses the complete movement stream. Flat wrapping skips void cells cyclically, including separated tile runs. Cube mode derives the face size from tile count, requires six full aligned squares and folds their right/down/normal frames through planar adjacency. Frames must be consistent and have six distinct normals.

The outgoing tangent identifies the destination face normal. Forward movement after crossing points toward the old face's inward normal. Comparing edge parameter axes determines whether to preserve or reverse the edge offset. This derives every transition for a valid cube net without hardcoded personal face links. A wall cancels both proposed position and facing. Official, personal, translated and side-one nets, blocked crossings and inverse edges are tested. An independent advisor approved the proof and inspected the implementation.

Day 23 builds all proposals from the old grove, then commits only unique destinations; every destination was previously empty. Priorities rotate after each round. Empty groves return zero empty bounding cells and stabilize on round one.

Day 24 computes hazard occupancy by inverse modular motion in the original map. BFS visits `(position, minute mod period)` once, permits waiting and uses parsed top/bottom openings. The period is the interior dimensions' LCM. Each return trip begins at the preceding absolute arrival time; independent personal arrivals are 322, 636 and 974. Exhausting finite states reports an unreachable destination.

Day 25 validates the five SNAFU digits and uses exact integer accumulation. Balanced-base encoding handles zero and negative totals as well as positive values.

## Resource contracts

Unsupported inputs and exhausted budgets return errors rather than partial answers. Whole-input parsing is capped at sixteen MiB. Forest and heightmap inputs are bounded at one million cells. Monkey inspections, sensor-row pairs, valve states, rock simulation/surface history, robot visits, mixing hops and expression size/arithmetic each have explicit bounds. Actual workloads fit these contracts.

Cube drawing size and traversal/void checks are bounded; face construction has six states. Elf diffusion limits both rounds and total elf visits. Valley parsing admits at most four million position-phase states, and each leg visits each state once. SNAFU numbers have at most 1024 digits and the input at most one million digits. These are algorithmic work/storage bounds, not peak-RSS guarantees.
