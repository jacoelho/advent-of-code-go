# 2015 migration

All 49 parts for 2015 are implemented. The ports use the original [Clojure source at `6018040`](https://github.com/jacoelho/advent-of-code-clj/tree/601804012ca87c06ff004daeb94bc3fd3064bf03). Twenty fixtures are unchanged resource files. Days 4, 10, 11, 20 and 22 turn inline source parameters into text fixtures; hashes distinguish the seed text from the fixture newline.

## Evidence

QA independently calculated all 49 expected answers without using Go outputs. [Answers, hashes and provenance](2015-oracles.json) include a valid 207-step derivation for day 19. These results agree with the source test assertions; they are not Advent of Code accepted-answer receipts.

The [independent oracle](oracles/2015.py) accepts a checkout of the pinned Clojure repository and emits JSON. Day 19 replays the recorded derivation and checks its matching lower bound; it does not depend on finding another random witness.

## Corrected source behavior

- Day 11 requires two different pair letters; four copies of one letter do not qualify.
- Day 14 awards every tied leader a point and includes the final second. A small asymmetric tie case is tested in both input orders.
- Day 16 treats an observed zero as a supplied value.
- Day 17 returns the number of minimum-size combinations, rather than that minimum size. Equal-capacity containers remain distinct.
- Day 20 uses a ceiling when converting the requested presents into elf contributions.
- Day 24 verifies that the remaining packages can form all remaining equal-weight groups. A regression rejects the tempting but impossible QE 340 arrangement and accepts QE 1120.

## Design and reference comparison

Days 1–6 use direct scans, box arithmetic, visited positions, sequential MD5 enumeration, earliest-pair positions, and a flat light grid. Day 7 evaluates wire dependencies with uint16 values and a fresh memo for the override. Day 8 delegates literal decoding to the standard library. Day 9 enumerates complete routes; day 10 encodes runs; day 11 advances passwords while skipping forbidden-letter ranges; day 12 traverses decoded JSON. The [Rust references](../reference/.repos/takemyoxygen--advent-of-code/2015) informed days 7, 11, 12; their same-letter password-pair acceptance was not adopted.

Days 13–18 were compared with the [Scala references](../reference/.repos/maneatingape--advent-of-code-scala/src/main/scala/AdventOfCode2015). Seating uses subset dynamic programming with one fixed guest. Race distances use complete cycles and a partial cycle; scoring credits all leaders. Cookie quantities are nonnegative compositions summing to 100. Aunt matching uses only explicit observations. Container counting tracks counts by capacity and minimum container count. Lights evolve synchronously, with stuck corners enabled before the first step. The Scala day 18 assumption of fixed 100×100 dimensions and its missing initial corner forcing were not copied.

Day 19 uses minimum-cost grammar parsing only after checking that literal rule matches coincide with atom boundaries across the complete grammar alphabet. Each original replacement costs one; synthetic binary productions and unchanged atoms cost zero. Unit closure handles substitutions and cycles. If that guard fails, reverse breadth-first search preserves [literal overlapping replacement semantics](https://adventofcode.com/2015/day/19). This fallback requires noncontracting forward rules, giving a finite search space bounded by the target length; it can still be exponential. Contracting rules outside the guarded grammar return an explicit unsupported-input error. Neither path uses randomized retries or a guessed depth limit. The Scala reference's molecule-length heuristic was rejected because it can overestimate the remaining cost. An advisor reviewed this choice and independently checked the actual grammar's 207-step lower bound and witness.

Day 20 uses an elf sieve with a proven upper bound: each house receives its own elf. Day 21 enumerates legal equipment and compares integer turn counts. Day 22 explores player-turn states in increasing mana cost using the existing heap. Day 23 interprets six instructions with unsigned registers and recognizes repeated states. Day 24 searches the smallest first-group sizes, minimizes exact products, and checks remainder partitions. Day 25 computes the diagonal index and uses modular exponentiation. Compared with the [Clojure references](../reference/.repos/tschady--advent-of-code/src/aoc/2015), the sieve avoids repeated factorization and equipment enumeration needs no duplicate dummy rings. The Scala day 24 shortcut also omits the remainder check; it was rejected.

Domain bounds are explicit: the seating table supports up to 20 guests, cookie searches up to 10 million compositions, and package partitions up to 64 entries. These cover the original inputs and canonical examples. Big integers preserve cookie products, combination counts, package products and the code-grid exponent. No measured speedups are claimed for these new ports.

## Shared parsing helper

`convert.ScanNumber` now uses strict decimal parsing and checks conversion to the requested signed type. It rejects lone signs and overflow, accepts an explicit plus, and preserves syntax/range error identity. Tests cover signed and native widths, a defined integer type, and scanner error propagation. Day 20 trims once at its input boundary and calls this helper. The new ports also reuse existing scanner, grid, set and heap helpers where they fit.

## Verification

QA assessed the tests before they were written. Canonical examples, independent full-input goldens, source-defect regressions, and reader-error checks cover the new entry points. Focused race/shuffle tests pass for the completed ports and numeric helpers. The portable Python oracle was rerun successfully, matching every expected answer and all fixture hashes. Repository-wide race/shuffle tests, Staticcheck, `go mod tidy` and `git diff --check` passed. Completion review found no material issues. It independently replayed all 207 reverse replacements for day 19 and verified the matching lower bound.

The full migration remains active; see [current coverage and remaining work](README.md). Implementation coverage does not imply that the broader performance and idiom review is complete.
