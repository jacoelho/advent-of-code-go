# 2019 and 2020 bounded reference, idiom and style review

Reviewed 34 days: 2019 days 01–07, 09–15, 17, 19–25; 2020 days 01–06 and 20–25. Reviewed the shared 2019 Intcode owner once. The most important findings are the fixed day 11 answer, incomplete day 15 VM snapshots, invalid day 17 movement compression and undefined day 22 affine exponentiation. Smaller concrete counterexamples and error propagation failures are recorded below.

## Scope and evidence

- Review boundaries are recorded in the [migration status](../README.md#remaining-work). Applied the Go code-review skill, repository conventions and the supplied user instructions.
- Selected reference repository: `reference/.repos/maneatingape--advent-of-code-scala`.
- Verified reference HEAD: `063a22ee01c1d489f76851e4e4971b0b9b767903`.
- Every reference path in the tables below is relative to that exact repository root. Each listed source and the corresponding Go implementation were inspected. Existing tests were inspected for relevant contract coverage; this was not an exhaustive test-quality review.
- Excluded 2019/08 OCR, 2019/16 FFT and 2019/18 active work. Excluded 2020/07–19 because their completed batch has a separate owner/evidence record.
- No Go tests, builds, reference executions, oracle replays or performance measurements were run. Counterexamples below are static deductions and hand traces, proposed for QA assessment before dependent tests. No performance improvement is claimed.
- Reference agreement is not a correctness proof: the Scala implementations share the origin-revisit, fuel-bound and affine-series assumptions noted below. Those shortcuts should not be imported or used to dismiss the counterexamples.

### F1 — P1: day 11 returns a fixed answer and conflates the starting color with painting

Anchors: [day11.go:10](../../internal/aoc2019/day11.go#L10), [day11.go:17](../../internal/aoc2019/day11.go#L17), [day11.go:75](../../internal/aoc2019/day11.go#L75).

Part 2 computes and prints panels, then unconditionally returns `ZRZPKEZR`; another valid painting program therefore gets the personal answer. Part 1 seeds the black starting panel into the same map used to count painted positions: the halt-only program `99` returns one painted panel instead of zero. `runPaintingRobot` also turns `Run` errors or incomplete output into an apparently successful partial result.

Smallest fix: return painting failures explicitly, count only paint events, and decode the rendered white pixels through existing `internal/aoc` six-row OCR. The initial sensor color is not a paint event. A separate framework is unnecessary; omit the black origin entry for part 1 and keep the part-2 white seed only as rendering/sensor state, or represent the painted count explicitly if the common helper requires it. Remove `PrettyPrint` from the answer-producing path.

Verification needed: literal non-personal painted glyph/raster with independently known text; halt-only part 1 → `0`; VM/protocol failure reaches the entrypoint; preserve personal goldens. The personal OCR golden alone cannot detect the current defect.

### F2 — P1: day 15 branches a memory image, not the suspended machine

Anchor: [day15.go:84](../../internal/aoc2019/day15.go#L84); existing owner: [intcode.go:407](../../internal/aoc2019/intcode.go#L407).

`New(state.computer.Memory())` resets the instruction pointer, relative base, pending input and execution flags on every movement branch. Memory is only one component of an Intcode continuation. This happens to depend on the personal droid program's restart behavior rather than the VM contract.

Smallest fix: use `state.computer.Clone()`, already implemented in the shared owner, and return movement/VM errors instead of the panics at lines 87 and 92. Keep the maze/BFS model.

Verification needed: a small droid-like program that pauses with nonzero instruction pointer and relative base, then responds differently to later commands. Verify independent branches preserve the continuation without sharing mutable memory; retain both personal results. This is an existing VM capability, not a reason for a new snapshot interface.

### F3 — P2: day 17 compression can split numeric tokens and emit invalid routine syntax

Anchors: [day17.go:163](../../internal/aoc2019/day17.go#L163), [day17.go:213](../../internal/aoc2019/day17.go#L213), [day17.go:258](../../internal/aoc2019/day17.go#L258).

Candidates and replacements operate on substrings, while the machine consumes turn/count tokens and comma-separated routine names. For path `R,1,R,10`, the search can choose `A=R`, `B=1`, `C=0`, and accept main `A,B,A,BC`. All characters pass `tryCompression`, but `BC` is not one routine call and the candidate routines are not complete turn/count sequences. At [day17.go:285](../../internal/aoc2019/day17.go#L285), an ASCII rejection response can then be mistaken for the numerical dust answer.

Smallest fix: replace the substring-pattern helper chain with a bounded token-prefix backtracking search. Match complete token sequences; choose complete movement-pair prefixes; enforce the 20-character bounds when serializing functions and main; require expansion to reproduce the original path. Check that the robot produced a dust result rather than only an error transcript. This deletes `extractParts`, `generateUniquePatterns`, `extractPatternsFrom`, `tryCompression`, `findValidFunctionC` and `tryFunctionsBC` instead of layering another validator on them.

Verification needed: the literal multi-digit counterexample, a path requiring repeated functions, valid 20-character boundaries, exact expansion of accepted output and a rejected/ASCII-only machine response. The selected reference hardcodes routines, so it does not establish a generic compression algorithm.

### F4 — P2: day 22 exponentiation divides by a non-invertible value for valid shuffles

Anchor: [day22.go:127](../../internal/aoc2019/day22.go#L127), especially `modInv(a-1)` at line 141.

A cut-only shuffle has inverse `f(x)=x+c`, so `a=1`. `ModInverse(0,m)` returns nil, then the multiplication panics. Identity maps have the same issue. These are valid affine shuffles; prime deck size does not make zero invertible.

Smallest fix: exponentiate affine maps by repeated squaring using existing `compose`, starting from the identity. Delete the geometric-series division. This supports `a=1` without a special-case parallel formula and also avoids assuming `a-1` is invertible for other moduli.

Verification needed: cut-only repetition, identity, repeated new-stack, and a small literal deck whose repeated mixed shuffle is independently enumerated. Preserve the personal part-2 answer. The Scala reference repeats the same unsafe formula and must not be treated as corroboration.

### F5 — P2: the shared Intcode boundary rejects valid text and valid zero-extended parameter cells

Anchors: [intcode.go:59](../../internal/aoc2019/intcode.go#L59), [intcode.go:105](../../internal/aoc2019/intcode.go#L105), [intcode.go:125](../../internal/aoc2019/intcode.go#L125), and instruction-length checks in opcode execution.

The comma splitter passes the final newline directly to strict `convert.ScanNumber`; ordinary text `99\n` is rejected. Separately, `readMemory` correctly defines nonnegative unwritten memory as zero, but parameter decoding and opcode-length checks impose physical slice bounds first. The two rules conflict.

Hand-traced terminating program: `1101,99,0,0,1101,1005,0,20,1105,1,20`. It writes `99` at address 0 and `1005` at address 20, then jumps to 20. The unwritten parameter cells 21 and 22 read as zero; position-mode parameter 1 therefore reads address 0 as 99, and immediate parameter 2 jumps to address 0 and halts. Current bounds checks reject the instruction at 20.

Smallest fix: normalize permitted surrounding whitespace at the parser boundary while preserving malformed/empty token errors, then obtain instruction and parameter-cell values through the one zero-extending memory-read owner. Retain negative-address errors. Remove conflicting physical-slice checks, not the address-space contract. No generic VM interface, duplicate interpreter or broad rewrite is needed.

Verification needed: final LF/CRLF, malformed numeric tokens, the literal program above, existing relative-base/quine tests and explicit negative-address failure. Apply the fix once for all Intcode days.

### F6 — P2: day 14's binary-search interval excludes legal answers

Anchor: [day14.go:142](../../internal/aoc2019/day14.go#L142).

The maximum fuel is assumed to be at most the ore budget. Recipe `1 ORE => 2 FUEL` yields `2_000_000_000_000` fuel from the fixed budget, but the search cannot return more than `1_000_000_000_000`. Batch outputs make the assumed bound false.

Smallest fix: establish an infeasible upper bound by checked growth, then binary-search the feasible/infeasible interval. Arithmetic and growth must be bounded explicitly; do not introduce an overflowing doubling loop. Keep the existing required/leftover calculation. The reference shares this bound and does not justify it.

Verification needed: the literal one-to-two recipe, a recipe where leftovers alter the last affordable batch, existing canonical examples and the personal answers.

### F7 — P2: day 03 admits a revisited central port as an intersection

Anchors: [day03.go:116](../../internal/aoc2019/day03.go#L116), [day03.go:135](../../internal/aoc2019/day03.go#L135).

`traceWire` omits only the initial origin, not subsequent visits. For lines `R1,L1,U2,R2` and `L1,R1,D2,R2,U4`, the only noncentral common point is `(2,-2)`, reached after 6 and 10 steps. Answers must be `4` and `16`; the origin visit instead produces `0` and `4`.

Smallest fix: exclude the origin from the visited-intersection representation once, or explicitly skip it in both consumers. Preserve first-visit step counts. Verification needed: this independently hand-traced fixture plus the existing examples. Reference code has the same revisit blind spot.

### F8 — P2: day 07 assumes every candidate output is nonnegative

Anchor: [day07.go:33](../../internal/aoc2019/day07.go#L33).

Initializing `maxSignal` to zero yields a result not produced by any permutation when all signals are negative. Program `3,0,3,1,104,-1,99` reads both amplifier inputs and always emits `-1`; the part-1 maximum is `-1`, not `0`.

Smallest fix: initialize from the first candidate or a valid minimum sentinel. Verification needed: the literal negative-output program and existing amplifier examples; no extra permutation framework or performance work.

### F9 — P2: day 13 counts block updates instead of final screen contents

Anchor: [day13.go:23](../../internal/aoc2019/day13.go#L23).

Every output triple with tile ID 2 increments the count, even if the same position is later overwritten. Program `104,0,104,0,104,2,104,0,104,0,104,0,99` draws a block at `(0,0)` then clears it. The final screen contains zero blocks; current part 1 returns one. The selected reference folds updates into a map before counting.

Smallest fix: maintain final tile IDs by position, then count ID 2. Treat incomplete output triples as a protocol error while touching this boundary. Verification needed: the literal overwrite program, repeated identical updates, and the personal golden.

### F10 — P2: parser errors disappear or lose their original cause

Anchors: [2019/day20.go:84](../../internal/aoc2019/day20.go#L84), [2019/day24.go:46](../../internal/aoc2019/day24.go#L46), [2020/day22.go:48](../../internal/aoc2020/day22.go#L48).

The first two parsers do not return/check scanner errors, so truncated or failed reads become completed domain inputs. Day 24's immediate read failure becomes an empty grid and a successful zero answer. Combat checks the collected deck count before `s.Err()`, replacing a reader or number-conversion cause with `not enough decks`.

Smallest fix: return `(value,error)` from the two parsers, check the scanner error immediately after collection/iteration, and propagate it before shape validation. For combat, reorder the existing check rather than introduce another parser. While touching VM consumers, also preserve execution errors currently converted to `break`/`panic` in days 11, 15 and 19; their common cause is failure being mistaken for a domain result.

Verification needed: `errors.Is` against an immediate error reader and a failure after a valid input prefix, through both entrypoints where applicable. Reuse the existing shared reader-error testing boundary; do not duplicate per-day scaffolding.

### F11 — P2: day 21 of 2020 reports a partial allergen assignment as success

Anchor: [day21.go:97](../../internal/aoc2020/day21.go#L97).

When unresolved candidates have no singleton, the loop breaks and serializes only previously resolved allergens. Input `a b (contains x)` therefore returns an empty successful answer; a partially resolved input returns a plausible but incomplete dangerous-ingredient list.

Smallest fix: return an explicit unresolved/ambiguous or inconsistent-assignment error when propagation stops before completion, distinguishing an empty candidate set where useful. Keep candidate intersection and propagation; no general matching framework is needed merely to reject a domain outside the supported unique solution contract.

Verification needed: ambiguous single-allergen fixture, contradictory singleton ownership, canonical unique assignment and the personal answer. The reference's assumption that a singleton always exists should not be copied as panic behavior.

### F12 — P3: day 25 discards executed continuations and omits the initial subset

Anchors: [day25.go:107](../../internal/aoc2019/day25.go#L107), [day25.go:140](../../internal/aoc2019/day25.go#L140), [day25.go:250](../../internal/aoc2019/day25.go#L250), [day25.go:368](../../internal/aoc2019/day25.go#L368).

`tryCommand` clones and runs the VM but discards that continuation. Both exploration paths then clone and run the same accepted command again, ignoring the second error. Returning the executed machine alongside its text removes duplicated transitions and makes continuation ownership explicit. This is a direct code-path simplification, not a measured speed claim.

After dropping all items, the code tests only Gray-code changes; the initial empty inventory is never tried, so the reported “all combinations” search covers `2^n-1` subsets. Empty-item guards also prevent a zero-item solution. If the solver retains its exhaustive-combination contract, try the initial empty inventory once before the transitions and permit it through checkpoint discovery. If it deliberately supports only nonempty winning subsets, that limitation must instead be explicit; the personal golden does not establish it.

Verification needed: accepted command returns the continuation that produced its text; command failures preserve causes; a checkpoint accepting the initial empty inventory is not skipped; personal answer remains unchanged. Prefer an existing command/checkpoint seam or small literal VM fixture over introducing an interface solely for tests.

## Ownership, deletion and optional simplification

Keep one shared Intcode implementation. Its clone, input/output buffering, relative base and memory rules belong there, not in per-day simulators. Day-specific consumers own protocol meaning: paint/turn pairs, tile updates, droid movement results and ASCII/dust distinction. Reuse existing grid, deque, scanner, strict number conversion and OCR owners when their contracts fit.

Required simplifications accompany the correctness fixes: delete substring compression helpers (F3), replace the affine geometric-series path with composition (F4), remove competing physical-memory length rules (F5), and return the already-executed command clone (F12). These improve ownership without a new framework.

Two optional local changes are supported by the comparison but are not blockers:

1. [2020/day24.go:102](../../internal/aoc2020/day24.go#L102): accumulate neighbor counts once from black tiles, then apply the existing rule over that map. This can replace `neighbors`, `blackNeighborCount` and the separate candidate map. Retain axial coordinates. Verify the canonical 10/100-day counts and isolated/adjacent tile behavior if implemented; do not claim a speedup without measurement.
2. [2020/day20.go:88](../../internal/aoc2020/day20.go#L88) and [day20.go:153](../../internal/aoc2020/day20.go#L153): a canonical edge→tile-owner index could give matching-border counting and lookup one owner, mirroring the reference. It is not necessary for the accepted personal layout and should be omitted unless the resulting code is smaller and clearer. Do not add a generic tile framework or alter established orientation/monster behavior speculatively.

No change is recommended solely for use of a direct loop instead of a functional helper, for standard map/set representations, for already-local concrete types, or for unmeasured allocation claims. Do not replace the stronger cycle/state rules in 2019/12 or checked 2020/01–06 boundaries with shorter reference assumptions.
