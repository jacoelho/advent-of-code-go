### F1 — P1: 2025/12 discards the geometry required to answer the puzzle

[day12.go:14](/Volumes/External/Projects/advent-of-code-go/internal/aoc2025/day12.go:14), [day12.go:24](/Volumes/External/Projects/advent-of-code-go/internal/aoc2025/day12.go:24).

`shape` retains only area and `fitsAll` equates total occupied area with packability. In the official example all six shapes have area 7. The impossible third region requests seven shapes in a 12×5 region: 49≤60, so the Go rule counts it along with the two feasible regions. The required result is 2, not the statically derived 3. [Official example and placement rules](https://adventofcode.com/2025/day/12).

Smallest sound model: retain occupied cells/orientations; use area only to reject impossible cases. A disjoint bounding-box placement can certify easy positive cases, as in the selected reference. Cases between these bounds need a bounded exact placement search or an explicit unsupported/exhaustion error. Neither equality of personal goldens nor a necessary area test proves those cases. This material design needs the required advisor consultation before implementation.

Verification: official example, a shape whose area fits but dimensions cannot, and independently validated small packing cases including rotations/reflections. Keep the personal answer, but do not use it as the packing oracle. The existing test contains only that personal answer.

### F2 — P1: 2025/09 misses polygon edges entering through rectangle boundary endpoints

[day09.go:68](/Volumes/External/Projects/advent-of-code-go/internal/aoc2025/day09.go:68), [day09.go:112](/Volumes/External/Projects/advent-of-code-go/internal/aoc2025/day09.go:112), [day09.go:183](/Volumes/External/Projects/advent-of-code-go/internal/aoc2025/day09.go:183).

All four rectangle corners being inside, plus no *proper* segment crossing, does not establish containment in a concave polygon. Consider vertices in order `(0,0),(4,0),(4,4),(3,4),(3,1),(1,1),(1,4),(0,4)`. The 5×5 bounding rectangle has all corners on the boundary, but contains the exterior notch. Notch edges meet its top edge at endpoints, making the strict orientation-product test return false. Current validation accepts area 25. The largest valid red-corner rectangle is an arm of area 10.

The original proposed continuous edge-entry fix was superseded during contract verification: a notch between adjacent integer columns excludes no tiles. The completed [compressed lattice model](2025-geometry.md#rectangles) handles that case, the wide notch and degenerate rectangles exactly. The generic orientation/crossing machinery was removed.

Verification: the literal notch polygon → part 1 25 / part 2 10; boundary-touching valid rectangles, reversed polygon orientation and degenerate rectangles; existing official/personal tests. QA should confirm the lattice containment contract before tests are written.

### F3 — P1: 2024/24 warning rules are not a complete wire-swap solver

[day24.go:119](/Volumes/External/Projects/advent-of-code-go/internal/aoc2024/day24.go:119), [day24.go:174](/Volumes/External/Projects/advent-of-code-go/internal/aoc2024/day24.go:174).

`identifyWrongWires` returns outputs violating local operator/prefix rules. Swapping two correctly formed XOR sum outputs preserves every checked property. For example, start from a valid ripple adder of at least nine input bits and swap `z01/z02`, `z03/z04`, `z05/z06`, `z07/z08`. All four pairs are genuine swapped outputs, yet these rules flag none. The code neither identifies swap pairs nor verifies that repaired wiring computes addition.

Smallest sound approach: retain structural rules only as candidate pruning, then perform a bounded repair search/check over the supported adder structure and validate the complete repaired circuit. If supporting only a narrower detectable class, reject unsupported cases explicitly instead of returning a partial/empty list as success. Do not copy the reference's manually supplied personal swaps. Advisor consultation is appropriate for the chosen complete repair contract.

Verification: independently constructed valid adder with four known sum-output swaps, the actual eight names, and addition checks that exercise carry propagation. Existing part-2 tests on non-adder part-1 examples encode the current warning heuristic; they are not independent evidence of repair correctness and must be replaced/reclassified when the solver contract is fixed.

### F5 — P2: 2024/05 passes a partial order to a sorting API

[day05.go:68](/Volumes/External/Projects/advent-of-code-go/internal/aoc2024/day05.go:68).

Missing direct rules compare equal, but equality is not transitive: with `1|2` and `2|3`, 1 compares equal to 3 while both are ordered through 2. `slices.SortFunc` requires a strict weak ordering and does not promise a topological sort. Update `3,1,2` must become `1,2,3` (middle 2), but comparisons can leave the invalid update unchanged.

Smallest fix: topologically order the rules induced by pages in each invalid update, using an explicit deterministic tie rule and detecting cycles. Keep the existing validity test. A transitive-closure comparator still needs to handle incomparable pages soundly; direct topological ordering has the clearest contract. The reference repeats the comparator assumption.

Verification: the literal three-page chain, an already valid update, independent pages under the chosen tie rule, and canonical/personal results. Confirm repaired output satisfies every applicable rule, with independent expected middle values.

### F6 — P2: 2024/07 loses equations and its inverse search excludes legal zero behavior

[day07.go:14](/Volumes/External/Projects/advent-of-code-go/internal/aoc2024/day07.go:14), [day07.go:37](/Volumes/External/Projects/advent-of-code-go/internal/aoc2024/day07.go:37).

A map keyed by target drops repeated input rows. `10: 5 5` and `10: 2 5` are two satisfiable equations contributing 20, but only one survives. Separately, inverse multiplication executes `t%v` when `v=0`; `10: 2 0 10` is satisfiable as `2*0+10` but reaches that division. The heuristic also overloads residual zero as A*'s goal marker, and decimal suffix removal treats zero as having no digits.

Smallest fix: use a slice of equation records and one explicit reachability owner with a real terminal predicate. A memoized index/value search can remove the A* heuristic, cost and path reconstruction machinery; retain checked arithmetic and a declared state/work bound. If preserving inverse search, handle multiply-by-zero and the one digit of concatenated zero correctly rather than weakening the input domain silently.

Verification: repeated targets; a reachable and unreachable zero-containing equation; concatenation ending in zero; published/personal answers. The reference's row representation and direct operator semantics are useful, but its full combination enumeration need not be copied.

### F7 — P2: 2024/09 does not merge physically adjacent free intervals

Verification: `12023` → 12, adjacent zero-length cases and existing examples. Remove the unsupported “deleting is slower” comment unless a separately coordinated measurement supports it.
