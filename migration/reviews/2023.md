## Main problems

All counterexamples below are static deductions from the complete relevant paths, not executed regressions. They identify concrete input classes rather than requesting broad malformed-input hardening.

### F1 — P1: Day 19 range splits create ratings outside the incoming range

Location: [day19.go:142](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day19.go:142), used by processRange at line 280.

Both branches assign the threshold directly without intersecting with the incoming interval. These terminating workflows are sufficient:

    in{x<10:small,R}
    small{x<20:A,R}

    {x=1,m=1,a=1,s=1}

The first rule narrows x to 1..9; the second widens it to 1..19. P2 therefore counts 19×4000³ instead of 9×4000³ (576000000000). The C# implementation explicitly distinguishes none/all/partial matches against current bounds.

Smallest fix: clamp both halves to the incoming Min/Max, preserving an explicit empty interval. No new abstraction. Validation: nested same-category conditions, thresholds below/above/on either bound, all-match/no-match, and a tiny-domain exhaustive enumeration independent of interval splitting. Existing tests contain only the sample and personal golden.

### F2 — P1: Day 24 solves a restricted subset and never checks the full problem

Locations: [day24.go:72](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day24.go:72), [day24.go:134](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day24.go:134), [day24.go:159](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day24.go:159).

P1 rejects any vertical XY trajectory before testing intersection. For example, positions (300000000000000,299999999999999,0) and (299999999999999,300000000000000,0), velocities (0,1,0) and (1,0,0), meet at t=1 inside the requested bounds; Go returns no intersection.

P2 searches only velocities −500..500, computes XY intersections for stones 0..3, and never uses stone 0's Z condition or any stone after index 3 when accepting the rock. Appending a contradictory fifth trajectory cannot affect its answer. In the published sample, the first four stones meet rock position (24,13,10), velocity (−3,1,2), at times 5,3,4,6. Replacing the fifth stone by a stationary origin makes that rock invalid, but this implementation cannot observe the replacement. Relative epsilon at 10^14 coordinates also permits coordinate disagreement on the order of hundreds.

Smallest coherent replacement: determinant-based XY intersection with exact sign/bound checks; six unknown position/velocity components from differences of cross-product equations; select independent rows, solve, and validate a common nonnegative collision time for every stone in all three axes. The C# six-variable model is the useful idea; its decimal arithmetic and first-three-only acceptance are not a validation oracle.

Use standard math/big arithmetic locally. Existing [pkg/matrix/rational.go:43](/Volumes/External/Projects/advent-of-code-go/pkg/matrix/rational.go:43) multiplies int64 numerators/denominators without overflow checks, so forcing reuse is unsafe for elimination intermediates. Delete the velocity search, epsilon comparisons, adjusted-stone allocations, and Z guessing. Validation needs vertical/parallel/past/boundary intersections, a known rock outside ±500, degenerate first rows, a contradictory later stone, and exact nonnegative times. Keep existing sample/personal goldens.

### F3 — P1: Days 8 and 20 confuse first observations with synchronized periods

Locations: [day08.go:72](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day08.go:72), [day08.go:117](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day08.go:117), [day20.go:264](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day20.go:264), [day20.go:280](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day20.go:280).

Day 8 takes LCM of first Z hits, not actual cycle periods/residues. With one repeated L instruction, a path A→B→Z→C→B hits Z at 2,5,8,11; another A→B→C→Z→D→B hits at 3,7,11. Give each path distinct node names ending only its start with A and target with Z, and identical left/right destinations. The earliest common hit is 11; Go returns 6. An unreachable end loops forever.

Day 20 has the same unsupported period inference and additionally ignores persistent conjunction memory. This valid network first sends LOW to rx at press 3, while Go collects first HIGH times 1 and 2 and returns 2:

    broadcaster -> a, b
    %a -> con
    %b -> c
    %c -> con
    &con -> rx

At press 2, con remembers a=LOW, c=HIGH. At press 3, a becomes HIGH while c stays HIGH, producing the first LOW. The reference's own warning explicitly disclaims general topology support.

Day 8 fix: analyze finite states (node,instruction index), record transient hits and cycle residues, and combine compatible schedules; report unreachable/no-common-hit states. Reuse an existing exact congruence helper only if its modulus/overflow contract fits; do not create a generic scheduling framework.

Day 20 minimum truthful contract: observe actual LOW-to-rx during exact FIFO simulation; retain a fast extrapolation only behind a proven topology/state-cycle contract including phase and pulse ordering. Otherwise exact bounded state-cycle detection or an explicit unsupported-domain error is required. Observing two HIGH events is not sufficient proof, and adding only an early rx check does not repair large answers. Preserve personal-input performance through a justified fast path; parent should assign QA/advisor before implementing this contract. Validate offsets, remembered HIGH, multiple/no rx predecessors, and no-solution cycles. Do not share a “LCM first hit” helper between these different models.

### F4 — P1: Day 23 compression skips adjacent junctions and loses visited bits above 63

Locations: [day23.go:187](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day23.go:187), [day23.go:231](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day23.go:231), [day23.go:263](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day23.go:263).

followTrail is called with a junction's immediate neighbor. It never tests whether that current cell is already a junction; it chooses nextOptions[0] and only examines the following cell's degree. An adjacent junction's other exits disappear, and compressed edges can cross another junction without recording it. The junction set also deliberately includes start/end independently of degree, but the walker tests degree rather than that authoritative set.

Smallest fix: pass the junction set to the corridor walker and stop on current membership before choosing the sole continuation; retain edge lengths and parallel corridors. This makes the junction set the single stopping rule.

The separate uint64 visited mask silently discards shifts for indices ≥64. There is no construction bound, and map iteration randomly assigns those indices. Use one owned []bool with DFS push/pop, or explicitly reject an unsupported count before search; the direct slice avoids a hidden representation restriction. Reference's fixed 36-node topology does not justify the Go limit.

Validation: a small maze with adjacent degree-3 junctions, a start/end that also has degree 2, parallel corridors, and a graph beyond 64 nodes that is cheap to explore. Compare small cases against an independent cell-level longest-path search after QA assessment. Existing tests have only the sample and personal maze.

### F5 — P2: Four parsers turn reader failure into successful partial answers

Locations: [day03.go:32](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day03.go:32); [day15.go:24](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day15.go:24) and line 40; [day22.go:53](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day22.go:53), return at 83; [day23.go:46](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day23.go:46), return at 88.

These paths never inspect scanner.Err(). A reader that supplies a valid prefix then fails can produce a plausible answer with nil error. Day 15 also hides token-too-long errors on its single input line. The scanner helper already owns both conversion and reader errors; callers need only propagate them.

Smallest fix: return an error from parseSchematic, check Err after collection in the other parsers, and check Day 15 Scan/Err before processing. For Day 15, reading the intended single-line payload with an error-aware reader avoids the incidental Scanner token limit. No new scanner abstraction. Validate the original sentinel error survives a failing reader, including a valid prefix before failure; existing golden tests are insufficient for this boundary contract.

### F6 — P2: Day 21's mathematical shortcut has no enforced domain

Locations: [day21.go:60](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day21.go:60), [day21.go:89](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day21.go:89), especially 105/110 and 117–122.

P2 derives width from input but keeps the corner cutoff 65 and assumes the special centered tiling/parity geometry. On input S alone it returns N², N=26501365, while the repeated garden is the unobstructed plane and its exact-step reachable count is (N+1)². The reference documents its centered 131×131, clear-axis/border/diamond assumptions; Go neither documents nor checks them.

Smallest bounded fix is to state and validate the personal-input specialization before applying the formula, returning a clear unsupported-shape error otherwise. Deriving 65 from width alone is not a proof of the formula. Supporting arbitrary periodic gardens is separate substantial work, not required for this minimal repair. Validate the accepted fixture satisfies the actual proof conditions and rejected shapes do not receive a fabricated answer.

P1's distance/parity test also assumes a reachable edge permits two-step backtracking. A start enclosed by rocks has no exact positive-length walk, but is counted for every even target. Handle the isolated component explicitly; a tiny enclosed-start case establishes this without a general new search.

### F7 — P2: Day 6 floating roots lose exact integer endpoints

Location: [day06.go:44](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day06.go:44), particularly 57–58.

For time 2^54 (18014398509481984), distance 0, the valid holds are exactly 1..time−1. At that magnitude maxHold−1 rounds back to maxHold in float64; the returned count is time rather than time−1. This fits the parser's 64-bit int domain. The reference checks roots against the actual strict inequality; Go does not.

Smallest exact model: binary-search the first winning hold in the rising half, use symmetry for the last, and compare h > distance/(time−h) for positive denominators to avoid multiplication overflow. Check the midpoint can win before searching. Remove math.Sqrt/root rounding. Validate strict ties, no-win races, zero distance, and this large exact case; retain sample/personal tests.

## Concrete simplifications

### S1 — Day 14: one directional packing rule

[day14.go:56](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day14.go:56) encodes the same obstacle/next-free-cell rule twice, with axis and directionType enums, a per-call lookup map, and four nested iterator factories. Replace the iterator factories with direct signed loops; preferably let one small line-packing operation own the rule for either orientation. Preserve the current clone/return ownership unless all callers are deliberately changed together. This is a substantive deletion, not a demand to remove all iterators.

Keep full platformState keys and exact repeat arithmetic. Validate four directions on rectangular boards, obstacle-separated runs, and a short cycle with a nonzero remainder before adopting the change. No speed claim was measured.

### S2 — Days 19/20: reduce accidental API and representation boilerplate

[day19.go:16](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day19.go:16) through 213 exports a mini workflow API for a single solver, with repeated category switches and narration comments. [day20.go:18](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day20.go:18) through 179 exports a closed three-kind module interface plus separate structs that duplicate name/destinations and require a type assertion to initialize conjunction state. No qualified external consumers were found.

When the correctness paths are touched, make solver-local names private and domain-specific, remove comments that restate declarations/loops, and keep rule/memory invariants documented. A private module struct with a kind and one process switch can remove the interface, repeated methods and conjunction discovery map; one owner still holds all mutable network state. Category indexing into a four-element rating/range array can remove matching Get/Set switches if it improves the final file, but is optional rather than a prerequisite for F1.

Do not split these files into generic frameworks merely to reduce line counts. Keep FIFO pulse ownership and fresh per-call network state.

### S3 — Day 22: settle and discover support at the same boundary

[day22.go:142](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day22.go:142) and [day22.go:180](/Volumes/External/Projects/advent-of-code-go/internal/aoc2023/day22.go:180) can share one authoritative XY top-column map storing height and brick ID.
