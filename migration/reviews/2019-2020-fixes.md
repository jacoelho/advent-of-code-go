# Remaining 2019/2020 review corrections

This record supplements the [shared VM corrections](2019-intcode.md) and records the arithmetic, movement, continuation and failure-boundary fixes from the [original review](2019-2020.md). Reference revisions and per-day decisions remain in that review.

## Reactions and shuffles

Day 14 no longer assumes fuel is bounded by its ore budget. Checked doubling first proves an infeasible upper bound; the existing error-aware binary-search helper finds the first unaffordable fuel amount. A validated reaction DAG owns recipe dependencies. One topological demand pass combines all consumers before rounding an ingredient to whole batches, replacing nondeterministic repeated expansion and leftover bookkeeping.

Quantities use the shared strict signed-number parser. Duplicate products, ORE-producing recipes, missing dependencies and cycles fail at parsing. Limits are 4 MiB, 4,096 recipes, 65,536 ingredient mentions and 128-byte uppercase names. Each cost query visits each recipe/input once. Demand addition and multiplication must fit nonnegative `int64`; overflow returns an error rather than being interpreted as infeasibility. Part 2 requires a representable infeasible upper bound. This is an explicit arithmetic admission limit, not support for arbitrary-size reaction networks.

Day 22 raises the inverse affine map by repeated composition from identity, using at most 64 exponent bits. The geometric-series division by `a-1` is deleted. This handles identity, translations and composite moduli without separate formulas. Noninvertible increments return errors through inverse composition. Existing instruction interpretation and part-1 tracking remain unchanged; input is bounded to 4 MiB and 100,000 instructions.

Independent regressions include `1 ORE => 2 FUEL` producing two trillion fuel, a batch-rounding case whose last affordable fuel quantity is 222,222,222,222, cut-only repetition, identity and a literal ten-card deck after three mixed shuffles. The composite deck also covers an invertible affine multiplier with noninvertible `a-1`. Existing canonical and personal results pass.

## Intersections, maxima and failed inputs

Wire tracing excludes the central port from its first-visit map even when a wire returns there. Both consumers report a missing intersection instead of formatting an integer sentinel. The two revisiting wires in the original review produce distance 4 and combined steps 16.

Amplifier maxima start at the minimum integer. Both fixed-five-phase callers return `-1` for a program that always emits `-1`, preserving the actual candidate domain.

Maze and bug-grid parsers return scanner errors before domain processing. Combat checks its scanner before validating deck count, preserving reader and numeric-conversion causes. Shared entrypoint tables cover immediate and partial reader failures with `errors.Is`, using the standard `iotest.ErrReader`. A malformed combat card retains its `strconv.NumError`.

Allergen propagation rejects empty candidate sets and stops with an explicit unresolved-assignment error if non-singleton candidates remain. Lack of a singleton alone does not prove multiple assignments; no general matching claim is made. Tests cover a genuinely ambiguous input and two inconsistent inputs; the existing unique sample/personal assignments still pass.

## Scaffold movement

Compression now searches complete turn/count token prefixes. A function matches whole tokens and consumes complete movement pairs; substring replacement and its helper chain are deleted. A private movement-program value owns the main line and three definitions. Existing strict numeric conversion validates counts.

The protocol permits three functions of at most 20 ASCII bytes and at most ten main calls. Consequently a representable route has at most 50 pairs and 209 expanded bytes. The local search names functions in first-use order and consumes the entire route; renaming functions in that order does not restrict encodings. Unused definitions reuse the first function. Search stops after one million states with an exhaustion error, distinct from a completed search finding no encoding.

Robot execution sets free-play memory on a fresh VM and requires halt with one terminal dust value above the byte range; earlier values must be bytes. ASCII-only rejection text no longer becomes a dust answer. Missing/multiple robots and repeated route position/direction states fail before compression. Finite straight runs and at most four directions per scaffold position bound route construction. Existing route choice remains unchanged; this is not a general alternative-route solver.

Independent tests reconstruct accepted token programs, cover the `R,1,R,10` defect, exercise an exact 209-byte expansion requiring ten calls and 20-byte functions, and reject provably unrepresentable routes. Literal VM programs distinguish terminal dust from ASCII, waiting and multiple numeric results. Existing alignment 76 and personal results 6448/914900 remain unchanged.

## Adventure continuations and inventory

`tryCommand` returns the executed clone and its drained text. Exploration and collection retain that continuation; their second execution of the same accepted command is deleted. VM failures propagate through mapping, item collection and checkpoint trials. Death/security text remains an expected rejected move. The private room representation no longer stores an unused parsed inventory, and queued state has an adventure-specific name.

Checkpoint discovery recognizes both weight rejection and a successful password response. Zero safe items are permitted. The inventory phase drops carried items, tries the empty subset once, then visits every remaining subset through single-item Gray-code transitions. Items are sorted for deterministic traversal. Limits are 16 safe items, 256 mapped rooms, and 100,000 collection/queued states; the item limit is checked before shifting to count subsets. Each command also retains the shared VM execution bounds.

Literal ASCII programs consume complete command lines. Tests demonstrate independent original/returned continuations, zero-item success through the answer entrypoint, empty and later winning one-item subsets, the item-limit error, rejected moves and nested opcode-error propagation. The personal password remains 2214608912. Absence of discarded duplicate execution is additionally verified from the code path, without a command-spy interface.
